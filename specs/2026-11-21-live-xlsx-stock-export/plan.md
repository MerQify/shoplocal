# Live Excel Stock Exports Behind Auth; No Generated Exports in public/ (plan)

Issue #1714. Requirements: `requirements.md`. Approved 2026-11-21.

**Goal:** the platform stock-export hub's Excel downloads return the vendor's current data, filtered
the way the operator chose, to a signed-in platform admin only. No generated export is served from
`public/` any more.

## Why this slice exists

#1642 (2026-11-17) fixed a broken Excel download. It pointed the xlsx path at workbooks
pre-generated by `scripts/product-templates/export-all-stock.ts` and committed under
`public/templates/`. The route answers `format=xlsx` with a 302 to those files, and
`PlatformExportHub.tsx` links straight to them. That caused two defects:

1. **Exposure.** Anything in `public/` is a Cloudflare static asset, served before the Worker runs,
   so the platform-admin check never applies. On 2026-11-21 all three production hosts returned
   `200` with no session for these files:
   - `aheed-food-centre-master-stock-export.xlsx`
   - `aheed-food-centre-stock-export.{csv,xlsx}`
   - `aheed-food-centre-essential-export.{csv,xlsx}`

   The master workbook includes a **Discount Codes** sheet and every inactive product. The repo is
   public, so the files are also in git history. This slice removes them from the site. It cannot
   remove them from history (see "Open items").
2. **Stale, unfiltered data.** The files are a snapshot of every product taken on 2026-11-17. The
   hub's Active / All / Archived and category filters change only the CSV links, so the operator saw
   "Is Active = FALSE" on almost every row and concluded the column was broken (the report that
   opened #1714).

The CSV downloads were already built live behind the same check, and they are correct.

## Scope (this slice)

- **Shared in-memory workbook builder.** Today the spreadsheet code (`@e965/xlsx` plus `fflate`) is
  in `writeWorkbook(path, sheets)` in `scripts/lib/read-spreadsheet.ts`. That function builds the
  bytes and then calls `writeFileSync`.
  - Move the byte-building part into a new runtime module, `lib/spreadsheet/workbook.ts`, as
    `buildWorkbook(sheets): Uint8Array`. Move with it the `SheetDefinition` / `SheetDataValidation`
    types, `UNIVERSAL_DROPDOWN_RULES`, `ESSENTIAL_DROPDOWN_RULES`, `columnIndexToLetter` and
    `buildColumnValidations`.
  - `buildWorkbook` uses `XLSX.write(..., { type: "array" })`, not `"buffer"`, so it does not depend
    on Node's `Buffer`.
  - `writeWorkbook` becomes a thin wrapper that writes `buildWorkbook`'s output. The script keeps
    working, and the two can no longer drift.
- **Sheet assembly in `lib/`.** The script currently builds each sheet's rows inline. Move that into
  `lib/product-templates/workbook-sheets.ts`, with one function per workbook:
  - `buildStockSheets` returns `Products`.
  - `buildEssentialSheets` returns `Products`.
  - `buildMasterSheets` returns the same seven tabs, in the same order: Products, Categories,
    Bundles, Promotions, Discount Codes, Filters & Attributes, Field Instructions.

  They take already-fetched records, so they are pure and unit-testable. The script and the route
  both call them.
- **The route builds xlsx live.** In `app/(admin)/staff/platform/stock-export/export/route.ts`,
  `format=xlsx` with `type` `stock`, `essential` or `master` now:
  - fetches the records through the same `fetch*ForExport` functions the CSV branch uses, with the
    same `status` / `category` parsing;
  - builds the workbook;
  - returns `200` with the xlsx content type, `attachment`, and `cache-control: no-store`.

  The workbook module is loaded with `await import(...)` inside the xlsx branch, so the CSV path
  does not pay for SheetJS at module evaluation. The blank-template types (`universal`,
  `universal-template`, `essential-template`) keep redirecting to the static blank templates. They
  hold headers and invented sample rows only, which was checked on 2026-11-21.
- **Filters in the Master workbook:**
  - Products honours `status` and `category`.
  - Categories, Bundles, Promotions and Discount Codes honour `status`, matching their CSV routes.
  - Filters & Attributes has no status, also matching its CSV.

  The hub text says so.
- **Hub links.** In `components/staff/platform-stock-export/PlatformExportHub.tsx`, the Master,
  Universal xlsx and Essential xlsx links point at the route with the current filter query, in place
  of `/templates/...`, and lose the `download="<static name>"` attribute. The filename now comes
  from the route's `content-disposition`.
- **Remove the generated files and keep them out.**
  - Delete the five generated `*-export.*` files from `public/templates/`.
  - `export-all-stock.ts` writes exports only to the gitignored `.import-reports/exports/`. Its
    writes to `public/templates/` are limited to the blank `*-template.*` files.
  - A guard test fails if any file under `public/` has `-export.` in its name, or if
    `public/templates/` holds anything other than `*-template.csv` / `*-template.xlsx`.
- **`/api/health` stops echoing raw error text.** It shows `db.error` and `reference.error` as
  `(e as Error).message` to anyone, and a Neon connection error can name the database host. Both
  become fixed strings, with the real message going to `console.error`. The `ok`, `reachable`,
  `configured` and `status` fields are unchanged, because `/ship` reads them.

## Filenames

Live downloads are named without the vendor's name, per the vendor-neutral UI copy rule. The pattern
matches the CSV branch, with `.xlsx`:
- `stock-<status>-export-<date>.xlsx`
- `stock-essential-<status>-export-<date>.xlsx`
- `master-<status>-export-<date>.xlsx`

## Risk: Worker bundle size and CPU

`@e965/xlsx` is about 1 MB unminified and is not in the Worker bundle today. Only `scripts/` imports
it. Loading it dynamically keeps it off the CSV path at run time, but it still ships in the upload.

R11 measures the gzip upload size before and after with `wrangler deploy --dry-run` and caps the
increase. **If the cap is exceeded, the fallback is a direct OpenXML writer on `fflate`**, which the
dependency tree already has. That writer would cover inline strings, column widths, autofilter and
list validations: the only features the sheets use. Switching would be a Build-time decision
recorded in `build-notes.md`. No requirement here names SheetJS.

CPU: about 6,100 AFC products × 62 columns is the largest workbook. R12 checks a real Master
download on staging, which holds the AFC catalogue, after the staging deploy.

## Deliberately excluded

- **Purging the files from git history, or making the repo private.** These are owner decisions.
  History rewriting needs force-pushes to ruleset-protected branches. On GitHub's free plan a private
  repo loses rulesets. Recorded on #1714.
- **Rotating the exposed discount codes.** This is an owner action in the staff panel, recorded on
  #1714. Code cannot do it safely on the owner's behalf.
- **Stock Mode `UNKNOWN`, empty barcodes / cost prices, and dietary flags.** These are genuine data,
  not export bugs (#1211 default). Age restriction is #1200.
- **The other operational exports** (`/api/staff/*/export`). They are already live and guarded.
- **The other routes checked in the 2026-11-21 audit.** All guarded, or public by design.
